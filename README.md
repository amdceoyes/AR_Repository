# AR_Repository
zero-to-one AR core
SportCross AR 视觉定位核心
这是一个基于 Python 和 OpenCV 开发的增强现实（AR）视觉检测项目。本项目作为 SportCross 运动系统的底层核心，实现了从 2D 摄像头画面到 3D 物理空间的坐标转换。
1. 什么是 ArUco Marker？
ArUco Marker 是一种专门用于计算机视觉定位的二进制方形标记。
外观：类似于简化版的二维码。
优势：具有极强的抗干扰能力，即使在光线变化或部分遮挡的情况下，电脑也能快速识别出它的编号和精确的四个角点。
2. 技术实现流程
本程序按照以下“积木模块”运行：
影像采集：调动摄像头硬件，针对 DELL 设备进行 640x480 分辨率优化，保证实时性。
标记检测：使用 ArucoDetector 在每一帧像素中搜索特定的 4x4 字典标记，锁定其 2D 像素坐标。
位姿解算：利用 solvePnP 算法，结合预设的相机内参（相机矩阵与畸变系数），将 2D 像素点映射为 3D 空间数据。
实时渲染：将计算结果转化为可视化坐标轴，并实时输出 X, Y, Z 位姿数据。
3. 核心数据解析：rvec 与 tvec
通过 solvePnP 算法，我们获得了两个至关重要的向量：
tvec (Translation Vector - 平移向量)：
代表 Marker 中心相对于摄像头的空间位置。
Z 轴：最为关键，它代表了物体离镜头的真实距离（单位：米）。
rvec (Rotation Vector - 旋转向量)：
代表 Marker 在空间中的旋转角度，决定了虚拟物体如何“贴”在标记表面。
4. 为什么坐标轴是稳定的？
我们能画出稳定的坐标轴，是因为我们解决了 PnP (Perspective-n-Point) 问题。通过已知的 Marker 物理尺寸（例如 5cm）和摄像头畸变参数，程序可以在数学上反推出摄像头与物体之间的唯一相对位置。只要算法在运行，虚拟的坐标系就会像钉子一样“钉”在现实的纸片上。

## 🧠 技术核心 (Technical Notes)
本项目核心逻辑在于 **PnP (Perspective-n-Point) 问题** 的求解：
1. **输入**：标记的四个角点像素坐标 + 相机内参矩阵 ($K$)。
2. **解算**：得到旋转向量 ($rvec$) 和平移向量 ($tvec$)。
3. **渲染**：定义立方体的 8 个顶点（世界坐标系），通过 $rvec$ 和 $tvec$ 投影回图像平面。

> **注意**：目前 Z 轴设为 `-size` 以实现向外生长的视觉效果（取决于相机坐标系定义）。

26.4.29## 🧩 模块化功能详述 (Modular Breakdown)
1. Keyframe 保存机制 (The Memory Saver)
**它是系统的“精简版笔记”。** 如果系统每一帧都记，内存会爆掉且充满废话。
 * **功能逻辑**：系统会实时监测当前相机位姿。只有当相机移动距离超过阈值（如 15cm）或旋转角度超过阈值（如 20^\circ）时，才会把当前帧的特征描述子和位姿打包成一个“关键帧”。
 * **核心价值**：将连续的视频流压缩成离散的空间节点。它是后续“认路（回环检测）”和“地图构建”的唯一参考基准。
 * **输入/输出**：输入当前位姿和描述子 \rightarrow 输出是否存入数据库的布尔值。
2. Loop Detection 回环检测 (The Relocalizer)
**它是系统的“记性”。** 解决视觉算法随时间产生的累积误差（漂移）。
 * **功能逻辑**：当系统移动时，它会不断拿当前看到的“视觉指纹”去和历史关键帧（Keyframe）库进行查重。如果匹配点数超过安全阈值（如 80 个点），系统就会判定：“我回到了曾经来过的地方。”
 * **核心价值**：提供“上帝视角”的修正信号。它能告诉系统：“虽然你的 PnP 算出来你在 A 点，但根据记忆，你其实在 B 点”，从而瞬间清空累积误差。
 * **输入/输出**：输入当前帧描述子 \rightarrow 输出匹配到的历史帧 ID 或 None。
3. IMU Assist 惯性辅助 (The Blind Navigator)
**它是系统的“平衡感”。** 在眼睛看不清的时候，靠内耳前庭撑住局面。
 * **功能逻辑**：利用手机陀螺仪输出的角速度（\omega），结合极短的时间步长（\Delta t），通过运动学公式 \theta_{new} = \theta_{old} + \omega \cdot \Delta t 实时推算姿态的变化。
 * **核心价值**：**高频与容错。** 它的输出频率远高于视觉（100Hz vs 30Hz），且不依赖光照。在快速甩头或摄像头被遮挡时，它能保证 AR 方块不消失、不闪烁。
 * **输入/输出**：输入角速度和时间戳 \rightarrow 输出旋转增量 \Delta R。
4. System State Machine 系统状态机 (The Commander)
**它是系统的“大脑总调度”。** 决定谁在什么时候上场。
 * **功能逻辑**：它定义了一套严格的状态流转规则：
   * **INIT**：开机找 Marker。
   * **TRACKING**：视觉为主，IMU 为辅（计算稳定）。
   * **LOST**：视觉跟丢，切换到全 IMU 预测模式（紧急避险）。
   * **RECOVERING**：通过回环或特征匹配尝试找回位置。
 * **核心价值**：**系统鲁棒性（Robustness）。** 它把零散的算法整合成了一个有逻辑的软件实体。它让系统具备了“自知之明”，知道什么时候该信任谁，从而实现工业级的稳定性。
 * **输入/输出**：输入各个模块的状态反馈 \rightarrow 输出当前系统的全局运行模式。
